# PR 설명 작성

## 개요

이 skill은 igmo 저장소의 PR 본문을 기존 템플릿에 맞춰 작성한다. 처음 보는 팀원도 변경 전 상태, 변경 후 결과, 구현 맥락을 빠르게 이해할 수 있게 쓰되 너무 길게 늘리지 않는다.

## 기본 원칙

- `.github/PULL_REQUEST_TEMPLATE.md`의 섹션 순서와 `##` 제목을 유지한다.
- PR 본문은 한국어로 작성한다.
- 현상, 결과, 구현 내용을 섞지 않는다.
- 긴 코드 블록을 붙여 넣지 않는다. 코드가 이해에 필요하면 핵심 구조만 짧게 추상화해서 넣는다.
- 사용자가 설명을 따로 요청하지 않았다면 PR 본문만 출력한다.

## 섹션별 작성 기준

### `## As-Is`

- 반드시 불릿 목록으로 작성한다. 항목이 하나뿐이어도 `-`를 사용한다.
- 변경 전 현상이나 기존 동작을 적는다.
- 원인 분석, 구현 상세, 해결 방법을 적지 않는다.

### `## To-Be`

- 반드시 불릿 목록으로 작성한다. 항목이 하나뿐이어도 `-`를 사용한다.
- 변경 후 결과나 기대 상태를 적는다.
- 작업 목록이나 구현 방법을 적지 않는다.
- 사용자가 확인할 수 있는 동작, 리뷰어가 검증할 수 있는 상태, 시스템이 보장하는 결과 중심으로 적는다.

### `## 작업 내용`

- 실제로 무엇을 어떻게 바꿨는지 적는다.
- 대화 중 고민한 중요한 판단, 트레이드오프, 작업 맥락이 있으면 포함한다.
- 중요한 판단을 따로 보여주는 편이 이해에 도움이 되면 `### <판단 주제>` 소제목을 만든다.
- 너무 길어지지 않게 핵심만 남긴다.

## 버그 픽스 PR

버그 픽스라면 `## As-Is`에는 원인이 아니라 현상을 적고, `## 작업 내용` 안에 아래 소제목을 포함한다.

### 원인

버그가 발생한 직접 원인과 조건을 적는다.

### 해결 방법

원인을 어떻게 제거했는지, 재발을 막기 위해 어떤 상태를 보장했는지 적는다.
