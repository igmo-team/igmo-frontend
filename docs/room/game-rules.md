# IGMO 게임 규칙

> 이 문서는 프론트엔드가 게임 규칙을 이해하고 변경을 판단하기 위한 도메인 하네스다.
> 게임 상태와 점수의 권위는 백엔드에 있다. 현재 백엔드 구현과 다르게 동작하도록 추측해서 구현하지 않는다.

## 1. 전체 진행

```text
LOBBY
→ GENERATING
→ PLAYING
→ VOTING
→ RESULTS
→ PLAYING (다음 라운드)
→ ENDED
```

- `LOBBY`: 플레이어 입장과 준비
- `GENERATING`: 각 플레이어의 이미지와 원본 프롬프트 준비
- `PLAYING`: 현재 라운드의 추측 프롬프트 제출
- `VOTING`: 원본 프롬프트와 추측 프롬프트 중 하나에 투표
- `RESULTS`: 정답, 투표, 점수 공개
- `ENDED`: 모든 라운드가 끝난 뒤 최종 순위 공개

방장이 시작 요청을 보내면 방장은 자동으로 준비 완료 처리된다. 방장 외 모든 플레이어가 준비 완료이고 최소 인원 조건을 충족하면 `GENERATING`으로 진입한다.

이미지 준비가 끝나면 서버 설정값인 `image-generation-completion-delay`만큼 기다린 뒤 `PLAYING`으로 진입한다. 이 시간은 프론트에서 임의로 고정하지 않는다.

## 2. 게임 단위와 라운드 단위

| 정보               | 적용 범위 | 반복 주기             |
| ------------------ | --------- | --------------------- |
| 원본 프롬프트      | 게임      | 플레이어별 게임당 1회 |
| 생성 이미지        | 게임      | 플레이어별 게임당 1회 |
| 총 라운드 수       | 게임      | 라운드 생성 시 결정   |
| 누적 점수          | 게임      | 라운드 결과마다 갱신  |
| 출제자             | 라운드    | 라운드마다 변경       |
| 추측 프롬프트      | 라운드    | 라운드마다 제출       |
| 투표 보기와 투표   | 라운드    | 라운드마다 진행       |
| 라운드 점수와 결과 | 라운드    | 라운드마다 공개       |
| 최종 순위          | 게임      | 종료 시 1회 공개      |

> 이미지는 게임당 한 번 생성하고 모든 라운드에서 재사용한다. 라운드가 바뀌었다는 이유만으로 이미지 생성 상태를 초기화하거나 이미지를 다시 생성하지 않는다.

> 추측·투표·라운드 결과는 라운드마다 새로 발생한다. 이전 라운드의 개인 추측 상태를 다음 라운드에 표시하지 않는다.

## 3. 라운드와 역할

- 총 라운드 수는 라운드 생성 시점의 플레이어 수를 기준으로 한다.
- 각 플레이어는 한 게임에서 한 번씩 출제자가 된다.
- 출제자 순서는 게임 시작 시점의 플레이어 등록 순서다.
- 현재 라운드의 출제자 이미지는 이미지 준비 단계에서 생성한 이미지를 사용한다.

### 출제자

- 자신의 이미지와 원본 프롬프트가 현재 라운드에 사용된다.
- 현재 라운드에서 추측 프롬프트를 제출하지 않는다.
- 현재 라운드에서 투표하지 않는다.

### 일반 플레이어

- 출제자의 이미지를 보고 원본 프롬프트를 추측해 제출한다.
- 원본 프롬프트 또는 다른 플레이어의 추측 프롬프트에 투표한다.
- 자신이 제출한 추측 프롬프트에는 투표할 수 없다.

## 4. 이미지 준비

- 각 플레이어는 게임에서 사용할 원본 프롬프트를 제출한다.
- 정상적으로 생성된 이미지는 게임에서 한 번만 생성한다.
- 이미지 생성에 실패하면 프롬프트를 다시 입력해 재생성할 수 있다.
- 제한시간까지 프롬프트를 제출하지 않으면 서버가 준비한 샘플 프롬프트와 이미지로 대체한다.
- 대체된 샘플 프롬프트와 이미지도 이후 해당 플레이어가 출제자인 라운드의 정답으로 사용한다.

프롬프트 입력이 비어 있으면 프론트가 빈 프롬프트를 제출하지 않는다. timeout fallback은 서버가 처리한다.

## 5. 추측 프롬프트 제출

- 현재 라운드의 출제자 이미지를 공개한다.
- 출제자를 제외한 일반 플레이어가 추측 프롬프트를 제출한다.
- 일반 플레이어는 라운드당 기본적으로 하나의 추측 프롬프트를 제출한다.
- 제한시간이 끝났을 때 입력값이 있으면 서버가 자동 제출한다.
- 제한시간까지 제출하지 않으면 서버가 자동 추측을 생성한다.
- 다른 플레이어의 추측 프롬프트와 동일하면 제출을 거부한다.
- 원본 프롬프트와 비교할 때 앞뒤 공백은 제거하고 대소문자는 구분한다.

원본 프롬프트와 완전히 일치하면 다음과 같이 처리한다.

- 완벽 정답 점수 3점을 부여한다.
- 일반 정답 점수 2점은 추가로 부여하지 않는다.
- 완벽 정답임을 개인 화면에 알린다.
- 다른 가짜 프롬프트를 다시 제출하도록 한다.
- 가짜 프롬프트를 제출하기 전까지 해당 플레이어는 라운드 완료로 계산하지 않는다.
- 완벽 정답자는 현재 라운드에서 투표하지 않는다.

## 6. 투표

보기는 다음 항목으로 구성한다.

```text
출제자의 원본 프롬프트 1개
+ 일반 플레이어가 제출한 추측 프롬프트
```

- 보기 순서는 무작위다.
- 결과 공개 전까지 보기 작성자를 공개하지 않는다.
- 출제자는 투표하지 않는다.
- 완벽 정답자는 투표하지 않는다.
- 자신의 추측 프롬프트에는 투표할 수 없다.
- 투표 가능한 플레이어는 하나의 보기에 투표한다.
- 투표하지 않은 플레이어는 기권 처리한다.

모든 일반 플레이어가 완벽 정답이면 투표를 생략하고 바로 `RESULTS`로 이동한다. 이 경우 `VOTE_SNAPSHOT`이 오지 않을 수 있다.

## 7. 결과 공개와 종료

라운드 결과에는 다음 정보를 공개한다.

- 출제자
- 원본 프롬프트
- 각 추측 프롬프트의 작성자
- 각 플레이어의 투표 대상
- 라운드별 점수와 점수 상세
- 누적 점수

결과 화면에는 출제자 이미지를 표시하지 않는다.

결과 확인 시간이 끝나면 다음 라운드가 남아 있을 때 다음 `PLAYING`으로 이동한다. 모든 라운드가 끝나면 `ENDED`로 이동하고 최종 순위를 공개한다.

동점자는 공동 순위로 표시한다. 순위는 표준 경쟁 순위를 사용한다. 예를 들어 공동 1위 다음 순위는 3위다.

## 8. 플레이어 이탈

- 로비에서는 플레이어 제거와 방장 재선정이 반영된다.
- 게임 중 플레이어가 이탈해도 이미 결정된 라운드 수와 출제자 순서는 변경하지 않는다.
- 이후 서버 스냅샷에 반영된 현재 플레이어 수와 목록을 화면에 반영한다.
