# 검증 워크플로우

## 명령어와 실행 시점

| 명령어                 | 하는 일                   | 언제 실행                             |
| ---------------------- | ------------------------- | ------------------------------------- |
| `npm run typecheck`    | 타입 검사 (`tsc -b`)      | 코드 동작을 수정한 의미 있는 단위마다 |
| `npm run lint`         | ESLint 검사               | 기능 구현이 끝났을 때                 |
| `npm run build`        | 타입 검사 + 프로덕션 빌드 | 빌드·번들·라우팅·환경 설정 변경 시    |
| `npm run format:check` | Prettier 포맷 검사        | 문서·스타일·포맷 영향 변경 시         |
| `npm run dev`          | 개발 서버 실행            | UI 변경을 눈으로 확인할 때            |

## 워크플로우

1. 작업 시작 전, 수정할 파일에 해당하는 `.codex/instructions` 문서를 읽는다. (영역별 문서는 [AGENTS.md](../../AGENTS.md)의 라우팅 테이블 참조)
2. 코드를 수정한 경우 의미 있는 수정 단위가 끝날 때 `npm run typecheck`를 실행한다. 실패하면 다음 단계로 넘어가지 않고 즉시 고친다.
3. 기능 구현이 끝나면 `npm run lint`를 실행한다. error는 물론 warning도 새로 추가하지 않는다.
4. 수정한 영역에 해당하는 문서의 "커밋 전 체크리스트"를 실행한다.
5. 아래 종료 게이트에서 작업 종류에 맞는 검증을 실행한다.

## 종료 게이트

작업 종류에 따라 아래를 실행한다.

| 작업 종류                                                                       | 필수 검증                                                                    |
| ------------------------------------------------------------------------------- | ---------------------------------------------------------------------------- |
| 문서만 변경                                                                     | `npm run format:check`, `git diff --check`                                   |
| 코드 동작 변경                                                                  | `npm run typecheck`, `npm run lint`                                          |
| 빌드·번들·라우팅·환경 설정 변경                                                 | `npm run build`                                                              |
| 검증 인프라 변경 (`package.json`, `eslint.config.js`, `tsconfig`, Vite 설정 등) | `npm run typecheck`, `npm run lint`, `npm run build`, `npm run format:check` |
| UI 변경                                                                         | 위 검증 + 필요 시 `npm run dev`로 화면 확인                                  |

완료 보고에는 실행한 명령과 결과를 적는다. 실행하지 않은 검증이 있으면 이유를 적는다. 필수 검증이 실패한 상태에서 "구현했습니다"라고 보고하는 것은 금지다. 실패를 못 고치겠으면 실패 출력을 그대로 첨부해서 보고한다.

## 런타임 확인

- 이 프로젝트에는 테스트 러너가 없다. **테스트 파일을 만들지 않는다.**
- 화면에 보이는 변경(컴포넌트, 스타일, 라우팅)을 했으면 `npm run dev`로 해당 화면을 직접 띄워서 확인한다. 타입체크 통과만으로 "동작한다"고 판단하지 않는다.
